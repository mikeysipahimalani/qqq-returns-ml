# QQQ Next-Day Return Forecasting and Strategy Evaluation

An end-to-end quantitative finance research project using historical QQQ prices, price-derived indicators, linear regression, and tree-based machine learning to forecast next-trading-day **close-to-close percentage returns**. The project then asks a separate, practical question: do these forecasts support a profitable, executable trading rule?

**Headline result:** A tuned Random Forest modestly reduced held-out forecasting RMSE (about 2.17% versus the zero-return baseline) relative to constant-return baselines. A subsequent next-open-to-close long/cash trading rule was **not profitable**, even before assumed transaction costs. These are distinct findings, and the project does not claim deployable trading alpha.

2. Activate it with `source .venv/bin/activate`, then install dependencies: `python -m pip install -r requirements.txt ipykernel`.
3. In VS Code / Jupyter, select the `.venv` kernel.
4. **For the saved historical snapshot:** start at notebook **02** and run notebooks **02 → 03 → 04 → 05** in order, using **Restart & Run All**. Notebook 02 regenerates the same feature and target definitions into `qqq_model_data.csv`. Notebooks 03–05 independently reload what they need; they do not depend on another notebook's in-memory variables.
5. Notebook **01** documents the original data exploration and downloads an OHLCV snapshot. **Rerunning its download cell may overwrite `qqq_prices.csv` with revised vendor prices**, which can slightly change downstream metrics. ## Data and prediction target

- **Asset:** Invesco QQQ ETF (`QQQ`).
- **Source:** Daily Yahoo Finance historical prices retrieved with `yfinance`, `auto_adjust=True`, and `actions=False`.
- **Historical price request:** January 1, 2010 through September 1, 2026 (`end="2026-09-02"` is exclusive).
- **Usable modeling observations:** **4,170**, dated February 2, 2010 through August 31, 2026.
- **Unit:** Features and targets are **percent**. An RMSE of 1.31 means about 1.31 **percentage points**, not a 1.31% relative error in the forecast.

For session *t*, the target is the following session's close-to-close percentage return:

\[
y_t = 100\left(\frac{C_{t+1}}{C_t}-1\right).
\]

Four predictive features use data known by the close of session *t*:

| Feature | Construction and motivation |
|---|---|
| `Daily_Return_Pct` | Today vs. prior-session close; tests possible short-term continuation or reversal |
| `Momentum_5d_Pct` | Past five-session close-to-close price change; recent trend |
| `Volatility_20d_Pct` | Trailing 20-session standard deviation of daily percentage returns; current volatility regime |
| `MA_Distance_20d_Pct` | Percentage distance from trailing 20-session simple moving average; relative trend/extension |

`shift(-1)` aligns the *next* return as a label with *today's* features. All rolling calculations look backward; no future prices are permitted in the four X columns. Rows with insufficient trailing history or unavailable future labels are dropped **after** feature and target construction.

## Chronological splitting and leakage prevention

The chronological 70% / 15% / 15% **position-based** split (before two omitted boundary observations) is:

| Partition | Observations | Dates | Purpose |
|---|---:|---|---|
| Training | 2,918 | Feb 2, 2010 – Sep 2, 2021 | Fit all models, estimate training-only mean |
| Validation | 624 | Sep 7, 2021 – Feb 29, 2024 | Compare models and tune forest parameters |
| Test | 626 | Mar 4, 2024 – Aug 31, 2026 | Final one-time model evaluation |

The last training and validation observations at each boundary are **omitted**, leaving a one-row gap before the next partition. Because row *t* carries a label based on *t+1*, this prevents a boundary observation's label from extending into the next period. Prices for training observations can still be used to compute trailing features for the subsequent period: historical information is available at prediction time.

Additional safeguards:

1. Sort/check trading dates and prohibit duplicates or missing model features/labels.
2. Never randomly shuffle financial time series across historical periods.
3. Fit each model and compute the constant-mean baseline using **training data only**.
4. Choose hyperparameters using **validation RMSE only** and freeze the choice before test evaluation.
5. Do not revisit model selection after viewing test results. Any further strategy research requires explicitly exploratory labeling or a new holdout.

These choices reduce identifiable forms of leakage and overfitting; they do not prove the model will generalize to future market regimes.

## Candidate models and selection

- **Zero-return baseline:** predicts 0% every day.
- **Training-mean baseline:** predicts the mean next-day return from the training period (~0.085826%).
- **OLS linear regression:** a simple fitted reference for linear effects.
- **Random Forest:** 200 trees, depth 5, minimum 20 observations per leaf as the initial nonlinear candidate.
- **Tuned Random Forest:** nine combinations of tree depth (3, 5, 8) and minimum leaf size (10, 20, 30), keeping 200 trees and random seed 42.
- **Gradient Boosting:** 200 estimators, learning rate 0.05, depth 2, minimum 20 observations per leaf.

Regularizing trees with bounded depth and minimum leaf sizes limits the ability to memorize noise. Comparing **training** and **validation** metrics checks whether an apparent training gain generalizes. RMSE is the selection criterion because large prediction errors are squared; MAE is reported as a secondary, less outlier-sensitive metric.

**Validation RMSE (percentage points; lower is better; rounded to six decimals):**

| Model | Validation RMSE |
|---|---:|
| **Tuned Random Forest** | **1.551357** |
| Zero baseline | 1.551776 |
| Training-mean baseline | 1.551973 |
| Initial Random Forest | 1.556383 |
| Gradient Boosting | 1.562895 |
| Linear regression | 1.566878 |

The tuned model's validation advantage is **extremely small**. It won under the preselected metric but did not demonstrate economically meaningful skill. The frozen model had **200 trees, maximum depth 3, minimum leaf size 10, random seed 42**. The selection grid itself introduces validation-overfitting risk.

## Final held-out forecasting performance

The selected model was re-fitted on the **training partition only** (without retraining on validation or test observations) and evaluated on the reserved 626 test observations:

| Model | Test MAE | Test RMSE |
|---|---:|---:|
| **Tuned Random Forest** | **0.934910** | **1.314286** |
| Training-mean baseline | 0.937274 | 1.340726 |
| Zero-return baseline | 0.945665 | 1.343452 |

Relative to always predicting zero, test RMSE was roughly **2.17% lower**. Predicted-vs-actual return correlation was about **0.2045**, while predicted return standard deviation (**0.2056 percentage points**) was far below realized standard deviation (**1.3418**). The model learned a weak and fairly conservative signal, not an accurate daily market forecast.

Impurity-based Random Forest feature importance was highest for distance to the 20-day moving average (~41.1%), followed by five-day momentum (~21.2%), daily return (~20.6%), and volatility (~17.2%). These are measures of tree usage, **not causal importance**; correlated features complicate interpretation.

## Executable trading experiment and its limitation

The model's target is *today's close → next close*. Computing today's closing-price features requires waiting until today's close. We therefore **cannot** assume execution at the same already-observed official closing price. The exploratory strategy instead generates an after-close forecast, then trades **next open → next close** when the forecast is positive; otherwise it stays in cash.

That changes the return interval: the trade excludes overnight price movement included in the prediction target. The backtest does **not** directly test whether the model predicts tradable intraday returns.

Assumed round-trip cost per active intraday trade was 0, 5, or 10 basis points (`1 bp = 0.01%`). The 5 bp buy-and-hold benchmark pays approximately 2.5 bp at initial entry and exit, and has substantial overnight exposure, so it is a contextual comparator rather than an exposure-matched control.

| Strategy | Test-period total return |
|---|---:|
| RF long/cash, 0 bp | −9.55% |
| RF long/cash, 5 bp | **−32.80%** |
| RF long/cash, 10 bp | −50.08% |
| Always intraday, 5 bp | −28.89% |
| QQQ buy-and-hold, 5 bp | +62.56% |

The model signaled a long position on **594 of 626 sessions (94.89%)**. While continuous forecasts had a positive ~0.1965 correlation with future intraday returns, the sign-based strategy's trading days averaged slightly negative intraday returns. The 0 bp strategy also lost money, so costs alone do not explain the result.

**Conclusion:** The tested strategy does **not** establish profitable trading alpha. Reworking the target to match execution, or using intraday data available before a proposed pre-close order, would be a new research question—not a retroactive correction of this held-out result.

## Limitations and potential next steps

- One ETF, one historical split, and no regime-by-regime or statistical-significance analysis.
- Minimal price-derived features, not a comprehensive market/macro/microstructure dataset.
- Validation tuning can capitalize on one regime even with conservative hyperparameters.
- Historical adjusted-price downloads can be revised. The original raw OHLCV file was not committed during the initial exploratory research; the saved snapshot was added during project cleanup. Accordingly, the original analysis is reproducible to reported precision, not guaranteed bit-for-bit from a new download.
- Strategy implementation ignores realistic order-book slippage, market impact, tax treatment, and interest on cash; risk-free rate is assumed zero for reported Sharpe ratios.
- Trading decisions and cost scenarios were examined **after** forecasting test performance was revealed; the strategy backtest is exploratory and not a second untouched holdout.

Possible **new** studies: open-to-close labels with after-close signals, pre-close features with executable closing-auction constraints, rolling walk-forward evaluation, multiple market regimes and ETFs, turnover-aware exposure controls, and significance/uncertainty estimates. None should be promoted as independent test results using this already-viewed period.

## Interview-ready summary

> Built a leakage-conscious QQQ return-forecasting pipeline with engineered momentum, volatility, and moving-average indicators, chronological train/validation/test splits, and OLS/tree-based comparisons. A validation-selected Random Forest lowered held-out RMSE by ~2.2% relative to a zero-return baseline, but an exploratory next-day intraday strategy lost money after realistic timing and illustrative transaction-cost assumptions. The main lesson was the difference between statistical forecast quality and executable trading performance.
